## What the header can show

Phase precedence is event complete, client-selection entitlement, wedding day, finalised, photographer review, awaiting client, then offer. A missing event date is treated as upcoming. Local day/complete comes from the project event date and event calendar. A projected finalised/review step can outrank lagging list data for phase selection. Table copy joins the dictionary's line breaks into spaces. ## Actions and writes

| Action | Path and result |
| --- | --- |
| Prepare offers | Group’s primary button opens Home. The portal wizard separately confirms Use All or Use Selected offerings. Use All patches disabled rows to offered and both paths set `config.clientSelectionPrepared: true`; existing queue blocker waits or reports conflicts for selected shot-list entities before portal creation. Group and Couple are independent records and decisions. |
| Client autosave | Portal store schedules a draft, route delegates to `savePortalDraft` callable. Session, plan, ownership, required section, date and quota validate. The shot adapter merges by ID, preserves hidden/protected rows and metadata, distinguishes draft and submitted selection, recalculates IDs/totals, and validates names/descriptions. Draft does not change owner. Network failure can leave local draft state ahead of received Firestore. |
| Client submit, skip, confirmation | Submit transaction persists merged selections and names, clears capture `isChecked`, sets `locked / photographer`, stamps `clientSubmittedAt`, and updates IDs/totals. Optional Skip sets `finalized / none` with skip markers. Confirm Review is a guarded client review transition to `unlocked / client`; it does not approve choices. Firestore triggers rebuild portal projection and notify on supported transitions. |
| Choose for client | `claimPortalSection` requires authorised photographer, included step and canonical unlocked list. Writes `locked / photographer` and clears revision fields. No write to `clientSelected`; review turns off selection toggles. Reopening a finalised list with claim is limited to Key People/Locations. |
| Approve choices | `updateStepStatus(...FINALIZED,NONE)` flushes this section’s queue first; unsettled edits block approval. `finalizePortalSection` requires selected step, appropriate entitlement, pre-wedding and stored canonical `locked / photographer`; writes finalised flag, status and approval stamps, then rebuilds projection. All-finalised trigger can disable portal access. |
| Check/edit/reset/timing | Offer toggles `isDisabled`; capture/reset changes `isChecked`. Structure save is a normalized list write with totals, while item edits/eligible offline timing writes use field patches. Local optimism can update header counts before the server accepts. The server revalidates against current status, permissions, quotas and base values; concurrent edits, remote deletion or ownership changes can conflict. Queue draining/retry and list refresh are different actions. |

## Issues and smallest improvements

1. **Separate the portal link’s availability from ownership.** A configured unlocked step plus the prepared flag can keep awaiting copy and the claim CTA visible after disable/expiry. Review can likewise remain visible after access closes. Decide which photographer actions should remain available on closed links, then drive wording and CTA off matching predicates in existing shot workflow/view helpers. Distinguish actual submission, photographer claim, optional skip, and approved choices. A retained prior `clientSubmittedAt` can report the old submission after a hand-back and later claim. Use a route/transition test with independently arriving list and projection snapshots. 2. **Make takeover truthful.** Either expose a tested existing selection write path for photographer-owned review or describe this current action as taking over for review only.
